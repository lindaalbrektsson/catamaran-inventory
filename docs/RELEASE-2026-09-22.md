# Combined media uploads and mobile onboarding release

The complete combined working tree passed lint, typecheck, production build, 601 automated tests (64 files), 344 browser checks (2 expected skips), and 229 Chromium/WebKit compatibility checks (1 expected skip). Automated tests include migration/RLS, OWNER/MANAGER authorization, trusted finalization, malformed bytes, request reconciliation and push recovery coverage. No application fixes were required during final verification. Browser timings: full suite 5.2 minutes, compatibility 8.2 minutes.

Documents now accept JPEG, PNG, WebP and PDF sources up to 30 MiB. Images use the shared decoder/orientation/adaptive JPEG processor and target a 5 MiB maximum; PDFs upload unchanged directly to private Storage. Receipts retain their 3 MiB target. Optional versioned Need photos use a 3 MiB target and the same capture/select/preview controls, with trusted server-only finalization. Task/Maintenance updates also reuse the shared picker.

Mobile onboarding offers installation and notification enablement only in appropriate supported contexts, with explicit user action and a three-day Not now preference. Existing session, push permissions, inventory freshness, location streaming and fra1 configuration remain intact. Home onboarding adds no database query. No new environment variables or external services are required. Smart Scan remains unavailable and no paid AI integration is included.

Production migration order:
1. `20260922000100_document_upload_limits.sql`
2. `20260922000200_need_photo_versions.sql`

The deployment is followed by a separately authorized QA-data cleanup. Cleanup scripts, private backups, credentials and browser sessions are not part of the release. Account/configuration/security audits, categories, locations and configuration are preserved. Disposable users follow the existing safe-deletion/deactivation mechanism.

Physical iPhone/Android verification remains required for camera launch, document text readability, large-photo memory behavior, installation and real push delivery while the PWA is closed. Automated WebKit/Chromium checks are emulation, not real-device certification. Existing PDF validation is retained; it is not a comprehensive PDF sanitizer. Private failed upload reservations remain linked for reconciliation rather than silently deleted.
